# IA 검사 방식 독립 검토 — Assertion 정확성

검토일: 2026-11-09

## 범위

이 검토는 추가한 IA 검사만 대상으로 한다. 기능 테스트 원본 `tests/module.test.js`, `tests/page.test.js`는 수정하지 않았다. IA 검사는 선택된 기존 테스트를 별도 Node 프로세스로 실행해 일부러 넣은 결함을 잡는지 확인한다.

## 테스트별 판정

| 테스트 | 판정 | 기대 결과와 Assertion 검토 |
|---|---|---|
| IA-01 | 적합 | 업데이트를 무시하면 M-29의 `.value === 'b'` Assertion이 `ERR_ASSERTION`으로 실패해야 한다. 실패 출력에 테스트 ID와 `글 입력칸 값`도 확인한다. |
| IA-02 | 적합 | 결과 HTML은 같게 유지하고 노드만 다시 만들면 M-34의 변경 기록 0건 Assertion이 실패해야 한다. 출력에서 `ERR_ASSERTION`과 `변경이 없어야 하는데`를 확인한다. |
| IA-03 | 적합 | `toVdom` 호출 중 DOM 속성을 바꾸면 M-02의 변환 중 DOM 변경 금지 Assertion이 실패해야 한다. 실패 코드와 고유 메시지를 확인한다. |
| IA-04 | 적합 | Patch 버튼을 무효화하면 P-03의 실제/기대 HTML strict equality가 실패해야 한다. 실패 코드와 `Expected values to be strictly equal` 메시지를 확인한다. |
| IA-05 | 적합 | 뒤로가기 버튼을 무효화하면 P-08의 이전 실제 영역 복구 Assertion이 실패해야 한다. 실패 코드와 `실제 영역이 처음으로 돌아가지 않았다`를 확인한다. |
| IA-06 | 적합 | Adapter 초기화 오류도 TAP에 `[M-29]`를 포함한 실패를 만든다는 조건을 재현한다. 그러나 오류에 `ERR_ASSERTION`과 기대 Assertion 메시지가 없으므로 IA matcher가 이를 결함 탐지 성공으로 받아들이지 않는지 확인한다. |
| IA-07 | 적합(범위 제한) | 폼 속성 대신 live property를 갱신하는 대조 Adapter로 M-29만 실행한다. `[M-29]`, pass 1, fail 0을 확인해 속성 반영 방식 차이 하나를 부당하게 거부하지 않는지 검사한다. 실제 별도 구현 전체를 검증하는 것은 아니다. |

## 요청한 검증 기준 대조

- **Assertion 정확성:** IA-01~IA-05는 각 결함에 대응하는 기존 Assertion의 실패 코드와 구별 가능한 메시지/연산자를 확인한다. 예전 방식처럼 자식 프로세스 종료 코드와 테스트 ID만 보지 않는다. 테스트 ID는 환경 오류 때도 출력될 수 있다.
- **거짓 양성·거짓 음성:** IA-06이 환경 초기화 오류의 오분류를 막는다. IA-07은 M-29에 한해 정상적인 다른 표현 방식을 통과시킨다. 다섯 결함 변형은 각 목표 테스트 하나를 이름 패턴으로 선택해 실행한다.
- **독립성·안정성:** 변형마다 별도 Node 프로세스와 환경 변수로 실행하므로 변형 간 DOM·모듈 상태를 공유하지 않는다. 최대 3개 동시 실행이며, 프로세스당 30초 제한이 있다. 자원이 부족하면 timeout으로 실패할 수 있지만 성공으로 오인하지 않는다.
- **Adapter:** `inspection-mutant-adapter.js`는 `BASE_ADAPTER`에 실제 Adapter를 위임한 뒤 테스트용 결함을 주입한다. IA-06/07은 의도적으로 초기화 오류 또는 대조 동작을 만든다. 실제 팀별 Adapter 호환성은 현재 설정된 Adapter 외에는 검증하지 않았다.

## 잔여 한계

IA-01~IA-07은 선택된 Assertion의 결함 탐지와 한 가지 대체 표현만 확인한다. 따라서 모든 기능 테스트의 입력·기대값과 모든 Adapter의 정확성이 증명되는 것은 아니다. 현재 대상 `mini-react` Adapter로 실행해 검사 정확도 테스트 7개가 통과했으며, 다른 Adapter 실행은 미검증이다.

## 최종 판정

**IA 검사: 적합(대표 결함 범위에 한함).** 기존 IA-01~IA-05의 문제였던 “환경 실패도 탐지 성공으로 볼 수 있음”을 실제 setup-error 대조군으로 막았고, 각 실패가 의도한 Assertion에서 발생하는지 확인한다. IA-07은 정상 대체 방식 하나에 대한 제한적인 거짓 실패 방지 검사다.

## 후속 수정 (2026-11-09, 정적 검토 지적 반영)

위 판정표는 수정 전 IA 기준이다. 정적 검토 결론은 "범위가 좁은 스모크 체크 수준"이었고, 세 가지 지적을 반영해 다음을 바꿨다.

| 지적 | 수정 |
|---|---|
| 결함을 잡았다고 세기 전에 원래 구현이 같은 테스트를 통과하는지 확인하지 않음 | 같은 파일 · 같은 테스트를 `MUTANT_KIND=baseline` 으로 먼저 돌려 통과해야만 결함 실행 결과를 센다. 이 확인이 실제로 막는지 새 IA-08 로 검사한다 (원래 구현이 이미 update 를 안 하는 상황 → 결함 실행만 보면 "잡았다" 지만 기준선에서 걸러진다) |
| 판정이 Node 출력 글자(`ERR_ASSERTION`, `pass 1` 등)에 기댐 | `selfcheck/ia-reporter.js` 의 구조화된 결과(테스트 이름 · failureType · code · operator · generatedMessage · 메시지 첫 줄)로 판정한다. 확인 중 Node 26 은 직접 적은 메시지 뒤에도 `'a' !== 'b'` 같은 비교 내용을 붙인다는 것을 발견해, 메시지는 첫 줄만 비교한다. `selfcheck/run.sh` 는 `--test-reporter=tap` 으로 형식을 고정했다 (Node 23 이상에서 grep 이 빈 결과를 내던 문제) |
| 한 경우 확인을 다른 구현 전체 통과로 해석 | IA-07 을 M-29 하나에서 모듈 테스트 전체 비교로 넓히고, 이름 · 문서를 확인한 범위대로 고쳤다. 넓히자 선택 테스트 M-41(J9, 당시 J7)이 이 정상 변형을 거부한다는 것이 드러났다. M-29 는 "속성 · 프로퍼티 어느 쪽으로 반영해도 됨" 이지만 M-41 은 속성까지 지우라고 요구한다. J9 결정 사항으로 남기고, IA-07 은 필수 테스트 차이만 실패로 세며 선택 테스트 차이는 진단 메시지로 표시한다 |

그 밖의 변경

- IA-04 · 05 결함을 버튼의 `click` 메서드 덮어쓰기에서 click 이벤트 차단(창 capture 단계, 기본 동작도 막음)으로 바꿨다. 테스트가 버튼을 어떤 방식으로 눌러도 결함이 유지된다. 버튼을 못 찾으면 결함 없이 지나가지 않고 오류로 끝난다
- 알 수 없는 `MUTANT_KIND` 는 바로 오류로 끝난다 (오타가 "결함 없음" 으로 돌지 않게)
- 테스트 이름 패턴을 `^\[M-29\]` 처럼 앞에 고정해 비슷한 ID 를 함께 고르지 않게 했다

실행 결과 (mini-react Adapter, Node 26.13.0) : 기능 테스트 55 + 검사 정확도 테스트 8 = 63 통과 · 실패 0. 다른 Adapter 에서는 여전히 실행하지 않았다.
