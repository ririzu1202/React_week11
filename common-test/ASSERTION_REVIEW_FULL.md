검증일 : 2026-11-09

## 범위와 방법

- 대상 : `tests/module.test.js` (M-01 ~ M-41), `tests/page.test.js` (P-01 ~ P-14), `lib/harness.js`, `selfcheck/inspection.test.js` (IA-01 ~ IA-08), `adapters/template.js`, `adapters/jonghwi.js`
- 방법 : **정적 검토**. 아래 판정의 근거는 테스트 · 하네스 코드와 SPEC.md 요구사항뿐이다
- 특정 팀원의 구현 코드는 근거로 쓰지 않았다
- 실행 기록 : mini-react Adapter 로 `npm test` 를 돌려 63 개 모두 통과했다 (Node 26.13.0)

## 2. 잘못되거나 누락된 Assertion

### 2-1. 검증 없이 통과할 수 있는 테스트

- **P-04** : 결과 비교가 없어서 Patch 가 아무 일도 안 해도 통과한다. M-35 ~ M-37 은 `assertSame` 을 함께 하는데 P-04 만 빠졌다
- **M-34** : 루트를 교체하는 구현은 변경 기록이 0 건으로 잡힌다 (관찰 범위 밖)
- 짝을 이루는 설계라 문제로 보지 않은 것 : M-02 · P-07 · P-11 · P-12
  - 모두 "아무 일도 안 함" 이 통과하지만, 그런 구현은 짝 테스트(M-01 · P-03 · P-08 ~ P-10)가 잡는다

### 2-2. 거짓 음성 (잘못된 구현이 통과)

- M-35 · M-36 · M-37 · P-04 : "요소 하나만 교체" 를 허용할 때 교체된 요소가 **바뀐 그 요소인지** 확인하지 않는다
- 글자 노드를 새로 만들어도 요소만 남으면 통과한다 (REVIEW.md 4 장에도 적힘)
- 누락된 입력
  - 글자와 요소가 섞인 자식에서 글자만 바뀜 (예 : `<p>a<b>b</b>c</p>` → `<p>x<b>b</b>c</p>`)
  - 자식 순서가 바뀌면서 속성도 바뀜
  - `style` 속성 변경
  - 인덱스로 비교하는 diff 가 흔히 틀리는 곳이라 추가를 권고한다

### 2-3. 기대값을 update 뒤에 계산함

- `assertSame` (module.test.js 42~44) 과 M-33 (140) 은 비교용 컨테이너 `target` · `t` 를 update **뒤에** 정규화한다
- VDOM 이 비교용 DOM 노드를 참조하고 patch 가 그 노드를 옮겨 쓰는 설계라면, 기대값 자체가 바뀌어 거짓 통과 · 거짓 실패가 모두 가능하다
- 권고 : update 전에 기대 문자열을 계산해 둔다

## 5. 수정 권고 (우선순위 순)

1. **P-04** 에 `assert.equal(pg.actualCanon(), expected)` 를 추가한다
2. **M-34** 에 `r.root === root0` 과 "이전 요소 모두 남음" 을 추가하거나, 관찰 대상을 컨테이너의 부모까지 넓힌다
3. **M-33** 에 `run()` 과 같은 `M.mount` 처리를 넣고, 기대 문자열을 update 전에 계산한다
4. **assertSame** 의 기대 문자열을 update 전에 계산하도록 `run()` 에서 미리 저장한다
5. **M-35 · M-36 · M-37 · P-04** 는 개수 대신 "바뀌지 않은 요소들이 각각 남았는지" 를 본다
6. **M-41 / M-29** 는 J9 를 팀이 정한 뒤 둘 중 하나를 맞춘다
   - 화면 값만 초기화하면 된다 → M-41 의 속성 검사 두 줄과 마지막 모양 비교를 뺀다
   - 속성도 지워야 한다 → M-29 의 "어느 쪽이든 됨" 을 고친다
7. **run()** 에서 `await M.update(...)` 로 비동기 구현을 허용할지 팀이 정한다 (지금은 동기만)
8. 글자 · 요소 섞인 자식 변경 입력을 CASES 에 추가한다
9. **P-13** 에 테스트 영역 비교를 추가한다 (J3 결정 뒤)

## 6. 미검증

- 2 · 3 장의 거짓 음성 · 거짓 양성 경로는 정적 분석이다. 일부러 만든 구현으로 재현하지 않았다
- 종휘 Adapter 실행, `selfcheck/run.sh` (종휘 구현 경로 · bash 필요)
- 민기 · 정혁 Adapter
- 실제 브라우저와 jsdom 의 차이 (레이아웃 · 포커스 · 이미지 `onerror`)

## 7. 최종 판정

**조건부 적합.**

- 필수 테스트 대부분은 요구사항(R1 ~ R8)에 맞는 기대값과 실제 동작을 검증하는 Assertion 을 갖고 있다
- 기대값은 손으로 쓴 문자열이 아니라 브라우저 파싱 결과로 만든다
- 다만 다음은 고쳐야 한다
  - P-04 : 아무 일도 안 하는 Patch 가 통과한다
  - M-34 : 루트를 교체하는 통째 다시 그리기가 통과한다
  - M-33 : mount 설계에서 거짓 실패할 수 있다
- M-41(J9) · P-13(J3) 은 팀 결정이 먼저다
- 교차 검증에 쓰려면 권고 1 ~ 3 을 반영하고, 다른 팀원 Adapter 로 실행해 봐야 한다
