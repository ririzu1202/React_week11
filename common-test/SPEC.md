# 미니 React Phase 1 — 공통 인수 테스트 명세

- 목적 : 세 구현(민기 · 정혁 · 종휘)에 **똑같이** 적용할 수 있는 블랙박스 테스트
- 보는 것 : 바깥에서 보이는 결과 (실제 DOM 의 모양 · 노드가 그대로 남았는지 · 버튼을 누른 뒤 화면)
- 안 보는 것 : Virtual DOM 의 모양, patch 목록의 모양, 함수 이름, 알고리즘
- 근거 원문 : 과제 「미니 React」 Phase 1 · 품질 절 (팀 공유 개요 노트 기준)

### 검사 방식의 정확성 (필수)

`selfcheck/inspection.test.js` 는 결함을 하나씩 넣어, 미리 정한 기존 Assertion 이 그 결함을 잡는지 확인한다. 이 검사는 `npm test` 에 포함되며 `npm run test:inspection` 으로 따로 실행할 수 있다.

판정 규칙

- **기준선 먼저** : 같은 파일 · 같은 테스트를 결함 없이(`MUTANT_KIND=baseline`) 먼저 돌린다. 원래 구현이 통과해야만 결함 실행의 실패를 "잡았다" 로 센다
- **구조화된 결과로 판정** : `selfcheck/ia-reporter.js` 가 테스트마다 이름 · 실패 종류(`failureType`) · 오류 코드 · 비교 연산 · Node 가 만든 메시지인지 · 메시지 첫 줄을 JSON 으로 내보내고, 판정은 이것만 본다. 사람이 읽는 출력(tap · spec)은 Node 버전마다 기본 형식과 문구가 달라 판정에 쓰지 않는다 (Node 23 부터 기본 출력이 spec, Node 26 은 직접 적은 메시지 뒤에도 비교 내용을 붙인다)
- **"잡았다" 의 조건** : 기준선 통과 → 결함 실행에서 목표 테스트 실패 → 실패 종류 `testCodeFailure` · 코드 `ERR_ASSERTION` → 기대한 그 Assertion 과 일치
- **범위** : 결함 하나를 기능 테스트 하나에 연결해 본다. 통과해도 다른 결함 · 다른 테스트 · 다른 Adapter 에서 맞다는 뜻은 아니다

| ID | 의도적으로 넣는 변화 | 기대 결과 |
| --- | --- | --- |
| IA-01 | update 가 아무것도 하지 않음 | M-29 의 `글 입력칸 값` Assertion 실패 |

## 3. 테스트 명세

### 공통 절차

- **모듈 테스트** (`tests/module.test.js`) — `run(이전 HTML, 새 HTML)`
	1. 이전 HTML 로 컨테이너 `div` 를, 새 HTML 로 비교용 `div` 를 만든다
	2. 둘 다 Adapter 의 `toVdom` 으로 바꾼다
	3. 이전 컨테이너의 요소 목록을 적어 두고, DOM 변경 관찰을 켠다
	4. `update(컨테이너, 이전 VDOM, 새 VDOM)` 을 부른다
	5. 결과 컨테이너와 비교용 `div` 를 **정규화 문자열**로 바꿔 비교한다
- **정규화** : 태그 · 이름공간 · 속성(이름순) · 글자(붙은 글자는 합침). 주석은 뺀다
- Adapter 에 `mount` 가 있으면 1 과 3 사이에 `mount(컨테이너, 이전 VDOM)` 을 부른다 (노드 참조를 VDOM 에 묶는 설계용)
- **페이지 테스트** (`tests/page.test.js`) — 테스트마다 페이지를 새로 연다 (상태 간섭 없음)
	- 샘플 HTML 이 구현마다 달라도 되게, 테스트 영역 HTML 을 읽어 **마지막 글자에 ` ★` 를 붙이거나**, **끝에 `<p data-common-test="1">` 를 붙여** 고친다
