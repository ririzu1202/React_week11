## 4. 미검증 사항 · 잔여 위험

### 정상 구현이 실패할 수 있는 경우

- **ES 모듈 · 번들러 구현** : jsdom 은 `<script type="module">` 을 실행하지 못한다 → Adapter 의 `page.open` 으로 직접 열어야 한다
- **비동기 렌더링** : 버튼 뒤 50ms 안에 화면이 안 바뀌면 실패 → `settleMs` 를 늘린다
- **루트 모양이 다른 변환** : `toVdom(div)` 가 자식 배열만 돌려줘도, `update` 가 그것을 받아 처리하면 된다. 받지 못하면 Adapter 에서 내 함수를 맞게 불러야 한다 (로직 추가 없이)
- **글자 앞뒤 공백을 다듬는(trim) 구현** : 결과가 새 HTML 과 달라져 실패한다. 의도한 설계라면 J4 로 논의
- **테스트 영역을 예쁘게 들여 쓰는 구현** : 글자와 요소 사이에 줄바꿈을 넣으면, 공백만 있는 글자가 아니라 글자 내용이 바뀌어 P-02 가 실패할 수 있다
- **jsdom 과 실제 브라우저 차이** : 레이아웃 · 이미지 로드 · 포커스는 jsdom 에서 확인 못 한다

### 결함 구현이 통과할 수 있는 경우

- **"바뀐 부분만" 은 요소 객체가 남았는지로만 본다** : 글자 노드를 매번 새로 만들어도 요소만 남으면 통과
- **기록 저장(R7)은 뒤로가기로만 확인** : 화면에 안 보이는 기록 오류는 못 잡는다
- **J2 (변경 없는 Patch 의 기록)** 는 화면으로 구분이 안 돼 테스트가 없다
- **입력값 · 체크 상태(프로퍼티)** : 속성만 비교한다. 사용자가 입력한 뒤의 `.value` 는 보지 않는다
- **이벤트 리스너** : Phase 1 원문에 없어 보지 않는다
- **스크립트 실행 차단** : jsdom 에서 이미지 `onerror` 가 안 일어나 페이지 단 XSS 는 확인 못 한다 (모듈 M-31 만)
